# torch-choice v1.0.7

Released: 2026-05-05

This release introduces a unified training interface, more accurate
Hessian-based standard errors, an AI-generated test suite, comprehensive
paper-replication material, and a fast UV-based setup path. It also fixes a
state-dict handling bug in `NestedLogitModel` and tightens validation in
`ChoiceDataset`.

The previous release was v1.0.6 (2024-04-26).

---

## Highlights

### Unified `.fit()` training interface

Both `ConditionalLogitModel` and `NestedLogitModel` now expose a single
`.fit(dataset, ...)` method that drives the full training loop and returns an
`EstimationOutput` object containing the regression table, log-likelihoods, and
post-estimation statistics. The previous top-level `torch_choice.run(...)`
entry point and per-model `.run(...)` shims are preserved for backward
compatibility, so existing scripts continue to work — but new code should
prefer `.fit()`.

```python
from torch_choice.model import ConditionalLogitModel

model = ConditionalLogitModel(coef_variation_dict={...}, num_items=K)
result = model.fit(dataset_train, num_epochs=500, learning_rate=0.01)
print(result.coef_table)
```

Implementation lives in `torch_choice/model/_fit_mixin.py`
(`ChoiceModelFitMixin`).

### Hessian-based standard errors

`parameter_std` (in `torch_choice/utils/std.py`) now computes coefficient
standard errors from the inverse of the loss Hessian instead of from a
per-parameter variance approximation. This matches the standard MLE
asymptotic-variance formula used by `mlogit` in R and produces more accurate
standard errors, especially for `NestedLogitModel`. `.fit()` invokes the new
routine automatically; the resulting standard errors appear in the returned
`EstimationOutput.coef_table`.

### `NestedLogitModel` state-dict fix

Cloning, checkpointing, or copying a `NestedLogitModel` no longer crashes when
the `lambdas` parameter is aliased across nests. Previously this surfaced as a
state-dict-mismatch error during the first `.fit()` invocation on certain nest
configurations. (`torch_choice/model/_fit_mixin.py`.)

### Stricter `ChoiceDataset` validation (**breaking change**)

`ChoiceDataset.__init__` now requires `num_users` whenever `user_obs` or
`useritem_obs` is given, and `num_items` whenever `item_obs` or `useritem_obs`
is given, and validates that the leading dimensions of those tensors match.
Mismatches that previously failed silently or produced cryptic shape errors
during training are now caught at construction time.
(`torch_choice/data/choice_dataset.py`.)

This **deprecates the v1.0.6 behavior of inferring `num_items` / `num_users`
from `item_index.unique()` / `user_index.unique()`**. That inference is unsafe
in practice: under train/val/test splits some items or users may be absent
from a fold, so the inferred dimensions would silently differ across folds and
produce mismatched embedding tables.

**Migration.** Pass the cardinalities explicitly:

```python
# v1.0.6 (no longer works when observables are provided)
ChoiceDataset(item_index=..., user_obs=..., item_obs=...)

# v1.0.7
ChoiceDataset(
    item_index=...,
    num_users=NUM_USERS,
    num_items=NUM_ITEMS,
    num_sessions=NUM_SESSIONS,
    user_obs=...,
    item_obs=...,
)
```

## New tutorials and replication material

- **Classroom MNL tutorial**
  (`tutorials/classroom_torch_choice_tutorial.ipynb`) — a self-contained
  walkthrough of multinomial logit suitable for teaching, including data
  preparation, model specification, fitting, and interpretation.
- **Paper replication package** under `replication/`:
  - `replication/paper_demo.py` (and `replication/run_paper_demo.sh`)
    reproduces the headline results from the torch-choice paper on the
    House Cooling and Mode Canada datasets and exposes them
    programmatically (regression table, log-likelihoods, runtime).
  - `replication/paper_performance_benchmarks/` provides an end-to-end
    pipeline (synthetic data generation → torch-choice fit → R/`mlogit`
    fit → comparison plots) for reproducing the runtime/scaling figures
    from the paper. A full run takes roughly 20 hours on a single
    machine; per-experiment subsets are selectable via CLI flags.
  - `replication/paper_replication_guideline.md` documents environment
    setup, the demo, and the benchmark pipeline.
- **AI-generated test suite** at `ai_generated_tests/` provides 13 pytest
  modules covering models, datasets, parameters, the formula parser,
  synthetic-data utilities, and import sanity. Run via:
  ```
  pytest ai_generated_tests/
  # or, after install:
  torch-choice-test
  ```
  Existing `tests/` continues to be the maintained suite for the core
  models; both directories are listed in the `pyproject.toml`
  `testpaths`.

## Setup and packaging

- **UV-based setup path.** A new `UV_SETUP.md` guide and
  `scripts/setup_uv.sh` script provide a fast, reproducible environment
  using the `uv` package manager:
  ```
  bash scripts/setup_uv.sh complete
  ```
- **TensorBoard** is now a declared dependency, enabling out-of-the-box
  logging of training curves through the PyTorch Lightning trainer.
- **`requirements.txt`** has been expanded to cover dev tooling
  (`pytest`, `black`, `isort`), documentation (`mkdocs`, `jupyter`), and
  benchmarking dependencies, so a single install reproduces the full
  development environment.
- **NumPy version pin.** The package now requires `numpy>=1.22,<2.0`
  pending downstream NumPy 2.x compatibility work.

## Documentation

- The mkdocs site is now rebuilt automatically by
  `.github/workflows/mkdocs_build.yml` whenever the documentation source
  changes, and the `recompile_website.sh` helper has been updated to
  match.
- README installation and verification instructions have been refreshed
  for clarity.

## Continuous integration

- A new `run_pytest.yml` workflow runs the full pytest suite on each
  pull request and push.

## Packaging fixes

- Removed the `torch-choice-benchmark` console script entry point.
  It pointed at `replication.paper_performance_benchmarks.run_torch_choice`,
  which was excluded from the installed package, so invoking the script
  after `pip install torch-choice` raised `ModuleNotFoundError`. To run
  the paper performance benchmarks, clone the repository and run
  `python replication/paper_performance_benchmarks/run_torch_choice.py`
  directly — see `replication/paper_replication_guideline.md`. The
  `torch-choice-test` console script (which runs the bundled
  `ai_generated_tests/` suite) is unaffected.

## Backward compatibility

This release is largely backward-compatible with v1.0.6, with one
intentional break around `ChoiceDataset` validation:

- `torch_choice.run(...)` and `model.run(...)` continue to work and now
  delegate to the new `.fit()` implementation.
- **Breaking:** `ChoiceDataset(item_index=..., user_obs=..., item_obs=...)`
  without explicit `num_users` / `num_items` now raises `AssertionError`.
  See "Stricter `ChoiceDataset` validation" above for the rationale and
  migration snippet.

If you encounter an unexpected regression, please open an issue at
https://github.com/gsbDBI/torch-choice/issues.

## Known limitations

- Apple Silicon (MPS) GPU training is **not** yet supported in this
  release — the underlying fix is on a development branch and is
  expected to ship in v1.0.8.
- Several additional `mlogit`-comparison tutorials (yogurt, electricity,
  cracker, LPMC, etc.) are likewise queued for v1.0.8.
